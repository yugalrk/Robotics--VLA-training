1 · Ingest

What we were given

  • 84 handover episodes, 30 fps, ~75 s each (LeRobot v3)
  • 490 cube-stacking episodes, 6 fps, as extra skill data
  • State / action: 16 values: 7 joints + gripper, per arm
  • 3 cameras at 224×224: head, left wrist, right wrist
  • An Isaac Sim scene of the robot, cart, box and tray

What we found

1

joint trajectory: all 84 handover episodes follow the same motion. Only the lighting changes.

10

held-out episodes for validation: the 3 darkest, 3 brightest and 4 random lightings (configs/splits.json).

So the policy can learn the motion, but not where to reach. That shaped everything after this.

2 · Dataset intelligence

New demonstrations without a new model

Move the box on a 5 cm grid over the cart. For each cell, shift the recorded gripper path to the new box position and solve inverse kinematics (damped least squares, joint limits, staying close to the recorded joints).

3 · Fine-tune

What we trained

  • ACT on handover only, and on handover + cubes
  • SmolVLA (vision-language-action, 450 M) fine-tuned from lerobot/smolvla_base
  • Curriculum: single-arm skills → bimanual → full task, with rehearsal
  • LoRA, gradient accumulation, crash-safe --resume
  • All on an 8 GB laptop GPU, ~25 min per run; policies act at 6 Hz in 20-step chunks

pi0 / pi0.5 need ≥ 24 GB, so they run through the same server protocol on a bigger machine.

5 · Version & serve · live

The policy server

One HTTP protocol for every model: GET /info, POST /reset, POST /act. The Isaac Sim scripts, the MuJoCo eval and the pipeline UI all talk to it.

  • --checkpoint: any LeRobot policy (ACT, SmolVLA)
  • --trajectory: the recorded handover as a closed-loop lookup (no model)
  • serving/fr3duo_pi05_server.py: pi0.5 via openpi in WSL
  • Runs on a different machine than the simulator if needed

What we learned

Findings and next steps

Findings

  • Data diversity is the bottleneck. One trajectory teaches the motion, not the reach.
  • Offline accuracy ≠ closed-loop success. SmolVLA's 0.015 rad error still gives 0/3 in a replica whose images look different.
  • The simulator gap is real: the hand-out Isaac scene lacks the recorder's override layers, so even the recorded demo doesn't grasp there. Our MuJoCo replica does replay it.
  • Language-conditioned policies need the exact training instruction.

Next steps

  • Replay the 136 box-grid trajectories in simulation, keep the successes, record them with images → new training data
  • Fine-tune on simulator-rendered frames to close the visual gap
  • Train pi0.5 on a ≥ 24 GB GPU through the same server
  • Promote models through the gates automatically after each run
